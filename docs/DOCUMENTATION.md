## Presentations and films

Two decks and two films, and the pairs answer different questions. The main deck
and its film explain **why the product is built the way it is**; the walkthrough
deck and the demo film show **how to use it**, in the order somebody actually
would.

| File | Contents |
|---|---|
| `Orange_Innovation_Radar.pptx` | The concept deck. What the product is, the concepts it rests on, what it has produced, and how it is built. Every figure on it is read live from the database rather than typed in. |
| `Orange_Innovation_Radar.mp4` | That deck, narrated, 12 min 22 s — with a live application demo cut into the middle in place of slides 10 to 21. |
| `Orange_Innovation_Radar_Walkthrough.pptx` | The demo deck. Seven chapters in the order the demo takes them: the radar and an opportunity space, role modes, the full-screen view and its four tabs, workflow, analytics, generation, and the Planner. |
| `Orange_Innovation_Radar_Demo.mp4` | The narrated product demo, 18 min 05 s. Seven chapters against the running application, in a **headed** browser — so the embedded PDFs actually render — and scrolled through rather than shown from the top. |
| `Orange_Innovation_Radar_Walkthrough.mp4` | **Superseded** by the demo above, and kept only as a record of the app as it stood in August. It predates the Planner, the pre-sales pack, the scoping conversation and sign-in, and it was recorded headless — so its brief tab is a grey box where the PDF should be. |
| `Orange_Innovation_Radar_Speaker_Notes.docx` | One page per slide: what is on screen, what to say, and an explicit cue to advance. |

## Rebuilding

```bash
python3 docs/generators/build_diagrams.py           # the 29 PNGs
python3 docs/generators/build_reference.py          # API.md and DATA_MODEL.md, from live code
python3 docs/generators/build_docs.py               # the two .docx files and the speaker notes

# The two decks put real screenshots on their slides, so this comes first —
# and it needs the app running, in a headed browser.
python3 docs/generators/build_shots.py              # /tmp/vid/shots

python3 docs/generators/build_deck.py               # Orange_Innovation_Radar.pptx
python3 docs/generators/build_walkthrough_deck.py   # Orange_Innovation_Radar_Walkthrough.pptx

# The films need the API on :8000 and the frontend on :5173, and the decks built.
python3 docs/generators/build_video.py              # the concept film
python3 docs/generators/build_demo.py               # the narrated product demo
```

`generators/build_reference.py` reads the running FastAPI app and the live SQLite schema, so
the API and data-model references cannot drift from the code. The narrative
documents are hand-written in `_build/*_content.py` and need judgement to update —
the build script only assembles them.

**The two film builds drive a real browser against the running application.**
Nothing in either is faked. `generators/build_demo.py` runs the browser **headed** on
purpose: a headless Chromium will not display an embedded PDF, and half of what
the demo shows is a document rendered on the page.
